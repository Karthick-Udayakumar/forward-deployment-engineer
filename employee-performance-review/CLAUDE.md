# Employee Performance Review Management

Two projects: `api/` (FastAPI + PostgreSQL, psycopg3, no ORM) and `react/` (React 19 + TS + Vite).
Spec: Testleaf "Requirements, Design and API Specification" (screens, tables, endpoints, business rules below).
Pattern and rationale: `../ARCHITECTURE_PATTERN.md`. `api/README.md` is the source of truth for the rules.

## Business rules (enforced server-side; the UI mirrors them for fast feedback)
- Ratings 1-5 (quality, delivery, teamwork). `average_rating = (q + d + t) / 3`, rounded to 2 decimals, calculated by the server only.
- One review per employee per period: `UNIQUE(employee_id, period_id)`, `INSERT ... ON CONFLICT DO NOTHING`, 409.
- Comments mandatory (trimmed, non-empty, max 2000).
- Only `Open` periods accept reviews (409 on a closed one). Periods are annual or half-yearly.

## API (base `/api`)
`GET /employees`, `GET /review-periods[?status=Open]`, `GET /reviews[?period_id&employee_id&limit&offset]` (total in `X-Total-Count`),
`GET /reviews/{id}` (404), `POST /reviews` (201; 404 unknown employee/period, 409 closed/duplicate, 422 invalid).
`/openapi.json` is generated by FastAPI; `api/employee-performance-review-openapi.json` is a snapshot. Regenerate it after any route or model change.

## Screens (react/)
Review List (mandatory: period + employee filters, Search, pager, View link), Submit Review form (mandatory: star ratings, comments, Reset/Submit),
Review Details (optional). Optional extras not built: edit, delete, department-average dashboard.

## Backend rules (api/)
- Layering, one direction: `main.py` (routes/HTTP) -> `models.py` (Pydantic), `service.py` (business rules), `repository.py` (all SQL) -> `database.py`.
  No SQL in routes or service. No HTTP errors or business rules in the repository.
- Server owns derived fields: `id`, `average_rating`, `created_at`. Clients never send them.
- Validate at the edge: Pydantic `Field`, `Query(ge/le)`, `Literal` for enums. Use `response_model=` on every route.
- Status codes: 201 create, 404 missing (`detail="Review ID 'X' not found."`), 409 conflict, 422 invalid input.
- Parameterized SQL only (`%s`). Dynamic WHERE built from fixed fragments. Lists take `limit`/`offset` (max 500) with a stable ORDER BY tie-breaker.
- Check-and-write in one statement (never SELECT-then-INSERT). CORS origins come from env, never `*`.
- Tests must not need a database: monkeypatch the `main.*` repository imports (see `tests/test_api.py`).
- Auth/role checks are not in the spec but are required before any real use (employees see their own reviews, managers their reports).

## Frontend rules (react/)
- Folders: `types.ts` (mirrors API shapes), `constants.ts` (`as const` enums, field lists, `CRITERIA`), `format.ts` (pure display helpers),
  `api/client.ts` (the only `fetch`), `api/errors.ts`, `hooks/`, `components/`.
- Components are presentational: props in, callbacks out. Hooks call the client. `App.tsx` wires them. No router, `useState<AppPage>`.
- Client: one `request<T>()` pipeline, always rejects with `ApiError{code,status,detail}`, timeout + AbortSignal, input guards throw TypeError/RangeError before sending.
  List calls return `Page<T>{rows,total}` using `X-Total-Count`.
- Hooks: abort in effect cleanup, ignore results after abort, `busy` in try/finally, branch on `isApiError` + status (422 field errors, 409 server message, network/timeout message).
  `usePagedList(active, fetchPage)` takes a stable `fetchPage`; changing it (filters) reloads, and the caller resets to page 1.
- Forms: `validate()` + `buildPayload()`, map server 422 onto fields, focus first invalid field, `noValidate`, `aria-invalid`.
- Always: `data-testid` on interactive elements/rows, labels tied to inputs, `StatusMessage` with `aria-live`, empty/loading/error states.
- Constants and helpers live in `constants.ts`/`format.ts`, not in component files (the `react-refresh` lint rule).

## Checklist for a new endpoint
Model/Query constraints -> repository fn -> service rule -> 404/409/422 documented -> test -> regenerate OpenAPI snapshot ->
type in `types.ts` -> fn in `client.ts` -> hook -> component -> `data-testid`.

## Commands
- API: `cd api && pip install -r requirements.txt && psql "$DATABASE_URL" -f schema.sql -f seed.sql && uvicorn main:app --reload` ; tests: `pytest`
- UI: `cd react && npm install && npm run dev` (port 5173, API URL via `VITE_API_URL`, default `http://localhost:8000/api`) ; `npm run build`, `npm run lint`
